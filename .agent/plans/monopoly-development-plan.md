## 1. 总览

**目标**：交付可在浏览器联机游玩的大富翁（2-6 人好友对局），按 P0 → P1 → P2 递进。

**角色约定**：本项目为单人主导 + AI 协作，任务表中的"角色"标注技能域（后端 / 前端 / 全栈 / 运维），不指代独立人员，用于识别并行窗口与技能切换点。

**里程碑总表**

| 里程碑 | 输入 | 核心产出 | 预估 | 出口标准（验收） |
|--------|------|---------|------|-----------------|
| M0 脚手架与部署 | requirements §6/§7、部署规范 | monorepo 四包骨架、可部署空服务（compose + nginx conf + 证书 + 备份登记） | 1.5 人日 | 域名 HTTPS 可达 `/healthz`；备份登记验证 OK |

## 2. 关键路径与并行策略

**关键路径（不可并行的最长链）**

```
M0-1 ──→ M1-1 ──→ M1-3 ──→ M1-4 ──→ M1-5 ──→ M2-2 ──→ M2-3 ──→ M2-8 ──→ M3-4 ──→ M3-7 ──→ M4-*
(骨架)   (契约)   (核心循环) (结算)   (单测)   (事件层) (重连)   (联调)   (交易)   (收尾)
```

- **引擎（M1）是全局心脏**：M1-3 / M1-4 是全项目单点风险，延期直接拖累所有后续里程碑；缓解：契约与数据先行（M1-1 / M1-2），单测驱动开发，每完成一个规则分支立即提交用例
- **M2 双线并行窗口**：服务端线（M2-1 → M2-2 → M2-3）与客户端线（M2-4 → M2-5 → M2-6/7）在 §9 接口契约确认后即可并行，M2-8 合流联调
- **M0 部署线可与 M1 并行**：引擎是纯本地模块、不依赖部署；M0-4/M0-5 可在 M1 期间穿插推进
- **M3 内部并行**：M3-1（拍卖）、M3-2（建房）、M3-3（抵押）相互独立可并行；M3-4 依赖 M3-3，M3-5 依赖 M3-2/M3-3

## 9. 风险与缓解措施

> 基础风险来自 requirements §11；以下为计划视角的细化与计划特有风险。

| 风险 | 影响 | 缓解措施 | 预警信号 |

| 域名解析/证书等待 | M0 延期 | 提前提交 DNS 解析；证书流程与 M1 穿插 | 解析未生效阻塞 M0-5 |
