## 2. 起始设置

- 玩家人数：**2-6 人** [本项目裁决]（经典支持 2-8，本项目上限收敛为 6 以保证节奏）
- 每人初始资金：**$1500**；初始位置：GO；初始无地产
- 先手：[本项目裁决] 房主默认先手，之后按加入顺序轮转（经典为各掷骰比大小，实现意义不大）
- 银行：现金无限；建筑物库存有限——**房屋 32 栋、旅馆 12 座**
- 地图地名：[本项目裁决] 首版采用经典美版译名（见上表）；棋盘数据完全 JSON 化，后续可整体替换为自定义主题（如城市地标），**仅替换显示名与文案，数值结构不变**

## 3. 回合流程（状态机）

```
回合开始
  ↓
[掷骰阶段] 玩家掷 2 颗骰子
  ├─ 三次连续双数 → 直接入狱，本回合不移动，回合结束
  ├─ 监狱中掷出双数 → 出狱并按点数移动（不获得额外回合）
  ├─ 监狱中非双数 → 累计留在狱中；第 3 回合强制付 $50 出狱并移动
  └─ 正常 → 按点数移动
  ↓
[移动阶段] 棋子逐格移动（前端动画）；经过或停在 GO 收 $200
  ↓
[结算阶段] 按落脚格类型结算（见第 4-8 节）
  ↓
[行动窗口] 仅当拥有可行动事项时开放：
  - 落上无主地产：选择"购买"或"放弃（触发拍卖）"
  - 掷骰前 / 回合结束前：管理资产（建房、卖房、抵押、赎回、发起交易）
  ↓
[结束判断] 若本回合掷出双数（且未入狱）→ 回到掷骰阶段再掷一次
          否则 → 回合结束，交给下一位未破产玩家
```

**执行约束**
- 所有阶段判定与结算由服务端在收到动作的同一事务内完成 [本项目裁决]
- 非当前玩家在他人回合内**只能**参与：拍卖出价、交易应答 [本项目裁决]
- 管理资产类操作允许在"掷骰前"与"结算后至回合结束前"两个窗口进行；移动到结算动画播放中禁止操作 [本项目裁决：为交互清晰性收敛经典规则的"任意时刻可建房"]

## 4. 购买与拍卖

**购买**：落到无主地产/车站/公用事业时，当前玩家可按挂牌价购买（资金不足则只能放弃）。

**拍卖**（经典规则，必选动作）：
- 玩家放弃购买 → 银行**立即拍卖**该地产
- 拍卖无底价（可低于挂牌价成交）；**所有玩家**（含放弃的玩家）均可出价
- [本项目裁决] 默认开启拍卖；提供房规开关可关闭（关闭后：放弃即流拍，地产保持无主）
- [本项目裁决] 拍卖形式：公开递增出价（加价幅度不限），出价最高者得；所有人放弃则流拍；单次出价窗口超时（默认 30 秒无人加价）即成交
- 玩家只能出到**当前现金额度**以内；玩家之间不得借贷（经典规则）

> **实施状态（2026-09-18）**：M2 阶段曾以"放弃即流拍"过渡；**M3 起已按本规格完整落地**（轮转询问队列、服务端 30 秒超时驱动裁决、银行清算逐块连拍）。

## 5. 租金结算

**地产租金**：查附表 A 租金表。
- 若业主拥有同色组**全部**地产，无建筑状态下基础租金 ×2（垄断加成）
- 有 1-4 栋房屋 / 旅馆时按租金表对应档位
- [本项目裁决] **抵押口径**：色组内任一地产处于抵押状态时，该色组其余地产**不享受**双倍租金加成（口径统一为"抵押即失去垄断"）；此项为开放决策点，可配置
- 抵押中的地产不收租

**车站租金**（按业主持有车站数量）：1 座 $25 / 2 座 $50 / 3 座 $100 / 4 座 $200

**公用事业租金**：
- 持有 1 座：移动所用点数 × 4
- 持有 2 座：移动所用点数 × 10
- [本项目裁决] 被卡片（"前往最近公用事业"）强制移动时，按卡片规则掷骰决定倍数基数

**收租顺序** [本项目裁决]：结算租金 → 若租客现金不足 → 进入套现窗口（第 13 节）→ 仍不足 → 进入破产程序（第 12 节）。

## 6. 建房与卖房

**建房前置条件**（全部满足）：
1. 拥有该色组全部地契
2. 色组内无任何抵押地产
3. 银行房屋库存充足

**平均原则**：只能建在同组中**房屋数量最少**的地产上（并列均可）；一次可建多间，但每次操作后仍须满足平均。不可以建在已抵押的地产上。

**旅馆**：4 栋房屋 + 1 次升级 = 旅馆（旅馆视作第 5 级）；建旅馆时 4 栋房屋退回银行库存；一块地最多 1 座旅馆。

**库存不足**：[本项目裁决] 简化为先到先得（经典规则为竞拍房屋，复杂度过高，不实现）。

**卖房（套现）**：
- 按半价卖回银行；必须保持平均原则（只能卖房屋最多的地）
- 旅馆可拆回 4 栋房屋（需银行有 4 栋房屋库存），或按 5 栋房计算价值售出

## 7. 抵押与赎回

- **抵押**：无建筑的地产可向银行抵押，获得**半价**现金；抵押期间不收租，地契仍归玩家
- **赎回**：支付 抵押值 + 10% 利息；利息不足 $1 向上取整 [本项目裁决，经典原意]
- **抵押地交易**：地产带押交易后，买方需选择：立即赎回，或保持抵押并向银行支付抵押值 10% 的交易税
- 抵押操作不改变归属；已抵押地产可随时赎回（拍卖/结算动画期间除外）

## 9. 机会与命运（卡牌系统）

**抽取流程**：踩到卡格 → 从对应牌堆**顶部**抽 1 张 → 执行效果 → 卡片放回牌堆底部。
例外：**出狱许可证（Get Out of Jail Free）**由玩家保留，可自用或交易；使用后放回牌堆底部。

**卡牌数据结构建议**（事件 DSL）：
```ts
interface Card {
  id: string;
  deck: 'chance' | 'chest';
  text: string;                 // 展示文案
  effects: CardEffect[];        // 效果列表（按序执行）
}
type CardEffect =
  | { type: 'moveTo'; tile: number; collectGo?: boolean }   // 前往指定格（是否过 GO 收钱）
  | { type: 'moveBy'; steps: number }                        // 相对移动（负数后退）
  | { type: 'moveNearest'; target: 'railroad' | 'utility' }  // 前往最近目标
  | { type: 'gain' | 'pay'; amount: number }                 // 收/付固定金额
  | { type: 'payEach' | 'collectEach'; amount: number }      // 给/收每位玩家
  | { type: 'goToJail' }                                     // 入狱
  | { type: 'getOutOfJailFree' }                             // 获得出狱卡
  | { type: 'repairs'; perHouse: number; perHotel: number }; // 按建筑数量付费
```

## 10. 入狱规则

**入狱方式**：踩到"入狱"格 / 抽到"立即入狱"卡 / 连续三次掷出双数。

**在狱中**：仍可收租、建房、抵押、交易，**不能移动**。

**出狱方式**（掷骰前选择）：
1. 掷出双数 → 按点数移动（**不获得**额外回合）
2. 使用出狱许可证 → 正常掷骰移动
3. 支付 $50 罚金 → 正常掷骰移动

**强制出狱**：第 3 回合结束时仍未出狱 → 必须支付 $50，并按当次点数移动。

## 11. 玩家间交易

**可交易内容**：现金、地契（地上无建筑）、出狱许可证。玩家间不得借贷。

**交易模式** [本项目裁决，参考 terragady 双模式]：
1. **私有报价**：发起方指定"给与清单 / 索取清单"，对方在限时（默认 60 秒，超时视为拒绝）内接受或拒绝；双方收到结果通知
2. **开放市场**：玩家挂价出售自有地产（或其他可交易物），房内任何人可买断，可随时撤回

**抵押地交易**：带押交易后买方须立即支付抵押值 10% 的交易税，或选择立即赎回。

**处理时机**：任意窗口期均可发起；多个交易并发时按发起时间先到先处理（经典"先商谈的先处理"）。

## 12. 破产与清算

**判定**：玩家现金不足支付债务时，先进入套现窗口（第 13 节）；套现后仍不足 → 宣告破产。

**清算规则**：
| 债主 | 清算方式 |
|------|---------|
| 某位玩家 | 全部资产（现金 + 地契 + 出狱卡）直接移交债主；抵押地移交时债主立即支付抵押值 10% 的交易税 |
| 银行（税金、罚款等） | 银行清偿后，其全部地产**立即无底价拍卖**；出狱卡放回牌堆底部 |
| 多位玩家（如"支付每位玩家 $50"） | 视为银行代为清偿，其全部地产立即拍卖（经典规则） |

**破产后**：玩家退出对局，转为旁观者（可继续观看与聊天）。

## 13. 套现机制（现金流不足窗口）

支付义务触发但现金不足时的标准操作顺序 [本项目裁决：提供 60 秒操作窗口，倒计时提示]：
1. 卖房（半价，遵守平均原则）
2. 抵押地产（半价）
3. 与其他玩家协商交易换取现金

窗口结束仍不足 → 破产清算。

> **实施状态（2026-09-18）**：M2 阶段曾以"直接判定破产并清算"过渡；**M3 起已按本规格完整落地**（CASH_WINDOW 阶段 + 60 秒服务端计时 + 凑足自动结算；支持主动宣告破产提前退出）。适用场景：租金、税金、卡牌罚款（含 payEach 多人清偿，由银行经手转付）、强制保释金。

## 14. 胜负判定

- **默认**：最后一位未破产的玩家获胜 [本项目裁决]
- **限时模式**（可选，P2）：到时后总资产最高者获胜；资产口径 [本项目裁决] = 现金 + 地产牌面价（抵押地产按半价计）+ 建筑物建造成本

> **实施状态（2026-09-18，M4-6）**：限时模式已落地——房规面板可选 60 / 90 分钟（默认关闭）；到点由服务端计时触发 `TIME_UP`，引擎按总资产裁决（平局先比现金、再按玩家顺位）；建筑成本口径：房屋数 × 建房价，旅馆按 5 × 建房价；结束时事件 `GAME_ENDED.reason = "time-up"`（默认结束为 `"last-standing"`），战绩计入 game_records。
